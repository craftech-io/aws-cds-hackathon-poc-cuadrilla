# FL-110 · Cierre de sesión

| Campo | Valor |
|---|---|
| Área | L · Alta propia, acceso y leads |
| Actores · canal | Invitado, usuario de consola · consola |
| Disparador | "Salir" |
| Reglas | ADR-0025 §1 |
| Pruebas | U `lib/auth/logout.test.ts` · UI `logout.spec.ts` |

Sin `SR` ni `SMK`: el `RevokeToken` real contra `poc` lo prueba la verificación desplegada de `docs/test-plan.md` §6.1 (fila "Logout y borrado"), fuera de la compuerta.

## Entrada

- `UI`: sesión iniciada de un invitado de origen `SIGNUP` y de un `SUPERVISOR` con el Cognito falso, que registra cada `RevokeToken` y rechaza el refresh de un token revocado.
- `U`: almacenamiento de tokens con id, access y refresh; `RevokeToken` mockeado.

## Pasos

**Local**

- U `lib/auth/logout.test.ts`: "Salir" llama `RevokeToken` con el refresh token y el cliente `ConsoleWeb`, borra los tokens del navegador (`lib/auth/tokens.ts`) y vuelve a la landing.
- UI `logout.spec.ts` (390×844 y 1440×900, es y en, con y sin movimiento reducido): "Salir" desde la consola y desde la portada del invitado ("Cerrar sesión") → landing; después, `/app/*` redirige a `/login`; el refresh del token revocado no renueva; ningún token queda en `localStorage` ni `sessionStorage`.

**Verificación desplegada · `docs/test-plan.md` §6.1**

- "Salir" con la cuenta de prueba revoca el refresh token: un refresh posterior con ese token falla.

## Resultado esperado

- El refresh token revocado no renueva la sesión.
- `/app/*` redirige a `/login`; el navegador no guarda ningún token.

## Oráculo

No aplica: no hay pasos que dependan del modelo.

## Evidencia

- Llamadas registradas por el Cognito falso (operación y cliente, sin tokens).
- Claves del almacenamiento del navegador después de salir (sin valores).
- Reporte de Playwright de `logout.spec.ts`, sin HAR ni tokens.
