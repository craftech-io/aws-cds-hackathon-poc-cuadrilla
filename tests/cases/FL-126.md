# FL-126 · Cuenta bloqueada por el operador

| Campo | Valor |
|---|---|
| Área | L · Alta propia, acceso y leads |
| Actores · canal | Operador, invitado, personal · script, web |
| Disparador | `npm run console:block -- --stage poc --username <usuario> --block` (o `--by-email`, con la dirección por la entrada estándar); `--unblock` para revertir |
| Reglas | ADR-0029 §11 |
| Pruebas | U `routers/account-block.test.ts`, `scripts/console/block.test.ts` · UI `phone.spec.ts` |

## Entrada

- `U`: la fila de un invitado con su `sub`, una sesión que ya pasó el código (`jti-1`) y otra con un código pendiente (`jti-2`); Cognito como un doble que registra los comandos (`AdminGetUser`, `ListUsers`, `AdminDisableUser`, `AdminUserGlobalSignOut`, `AdminEnableUser`).
- `UI`: `/api/*` que responde `403 ACCOUNT_BLOCKED` a todo, o que empieza a responderlo con la pantalla del código abierta.

## Costura de QA

Ninguna prueba llama a AWS ni manda un SMS: Cognito es un doble, el registro y `Runtime` están en memoria y el puerto `SmsSender` es `memorySmsSender`. El script no corre en CI ni en el stage desde una prueba.

## Pasos

**Local**

- U `routers/account-block.test.ts`: con el token vigente y la sesión ya verificada, después de `--block` todos los procedimientos del `appRouter` que piden principal (incluidos `account.session`, `phone.sendCode` y `phone.verifyCode`) → `ACCOUNT_BLOCKED` y ningún SMS nuevo; los pasos del código llamados directamente (sin la puerta ni su caché) → `ACCOUNT_BLOCKED`; la fila queda con `blockedAt`, Cognito recibe deshabilitar y cerrar sesiones, y no queda ninguna fila `PHONESESSION…` ni `PHONECODE#` de la cuenta; `--unblock` quita `blockedAt`, habilita al usuario y, pasado el minuto de caché de un contenedor, la sesión vieja → `PHONE_VERIFICATION_REQUIRED`; una cuenta sin fila → `NO_ROW` sin tocar Cognito.
- U `scripts/console/block.test.ts`: `--block` por usuario de Cognito: comandos en el orden `AdminGetUser`, `AdminDisableUser`, `AdminUserGlobalSignOut`, todos con el pool del stage; dos sesiones borradas; `--unblock` termina con `AdminEnableUser`; `--by-email` lee la dirección de la entrada estándar, la busca con `ListUsers` y la salida no tiene ninguna `@`; una dirección como argumento, dos acciones, ninguna, ni usuario ni `--by-email`, o sin `--stage poc` → error antes de llamar a nada.
- UI `phone.spec.ts`: una cuenta bloqueada ve solo "Cuenta bloqueada" con el link "escríbenos" a `https://craftech.io/contact/`, sin el botón "Enviar código" y sin ningún `phone.sendCode`; si se bloquea con la pantalla abierta, el siguiente paso muestra el aviso.

## Resultado esperado

- Una cuenta bloqueada no accede a nada ni dispara un SMS, aunque su token siga vigente y su sesión ya haya pasado el código; el desbloqueo la devuelve al ingreso normal con un código nuevo.

## Oráculo

No aplica: todos los pasos son deterministas.

## Evidencia

- Salida de vitest y reporte de Playwright de los archivos citados.
