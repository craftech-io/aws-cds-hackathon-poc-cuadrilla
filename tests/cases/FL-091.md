# FL-091 · WhatsApp vivo: eventos entrantes

| Campo | Valor |
|---|---|
| Área | K · Canal vivo y robustez |
| Actores · canal | Instalador (teléfono real) · WhatsApp |
| Disparador | Evento de EUM Social por SNS |
| Reglas | ADR-0002 |
| Pruebas | U `channels/whatsapp/inbound.test.ts`, `channels/whatsapp/media.test.ts`, `channels/whatsapp/phone-filter.test.ts` · SR `SC-17/2..4` (pendiente P-01) |

Excepción de `docs/test-plan.md` §2.1 hasta P-01: `sc-17-whatsapp-live.ts` existe con todos sus pasos y devuelve `SKIPPED_PENDING_P01` mientras `live` no está en los transportes.

## Entrada

- `SC-17`: clon de `wo-24817` en el mundo vivo, con el teléfono del CTO en `SeedOverrides.personPhones` (nunca en el repo ni en la evidencia).
- Desde el teléfono: un toque de botón, una nota de voz real con el guion que declara el ejecutor ("la ONU no prende la luz PON") y una foto real de un objeto que el ejecutor declara.

## Pasos

**SR · `SC-17`** (pendiente P-01)

1. `SC-17/2` [det] botón desde el teléfono.
2. `SC-17/3` [agent] nota de voz real (`GetWhatsAppMessageMedia` con el id de AWS + Transcribe).
3. `SC-17/4` [agent] foto real.

**Local**

- U `inbound.test.ts`: fixtures con la forma real (SNS con `SignatureVersion 2`, `context.MetaPhoneNumberIds[]`, `whatsAppWebhookEntry` como string JSON): texto, botón, interactivo, audio con `voice: true`, imagen; el mismo resultado que el sobre simulado para el mismo contenido; mundo vivo o `PHONELEASE#`.
- U `media.test.ts`: `GetWhatsAppMessageMedia` con el id de AWS del número y `metadataOnly` primero, destino `waMediaKey`.
- U `phone-filter.test.ts`: con ids de forma real (`phone-number-id-<32 hex>` y numérico de Meta), el evento propio pasa; un fixture con el id de AWS en el lugar del de Meta se descarta; `SigningCertURL` de otro host → rechazado; nunca lanza.

## Resultado esperado

- Mismo resultado que el simulador para el mismo contenido (botón resuelto por nonce, turno, validación).
- La media se baja a `Media/` con el id de AWS del número; `lastInboundAtReal` actualizado en la persona del mundo vivo.

## Oráculo

Fila **FL-091** de §4.3:

- `SC-17/3`: `GetWhatsAppMessageMedia` con el id de AWS del número; transcripción presente con las palabras del guion que declara el ejecutor (normalizador único) y confianza ≥ 0,55; un `REPLY` con cita ∩ secciones esperadas del guion (con "la ONU no prende la luz PON", ∩ {`DIAG-02`}).
- `SC-17/4`: media bajada a S3 y una `PhotoValidation` de la clase esperada (`PASS` o no `PASS`) para lo fotografiado, que declara el ejecutor, con la reacción coherente; alternativa: `UNSURE` si lo fotografiado es de la clase no `PASS`.
- Sin oráculo duro: la redacción; el motivo exacto. La fila se exige también mientras el resultado es `SKIPPED_PENDING_P01`.

## Evidencia

- Resultado por paso (`SKIPPED_PENDING_P01` hasta P-01).
- Con P-01 cerrado: claves de media, palabras del guion encontradas y confianza, veredicto y reacción; el teléfono solo como `phoneHash`.
