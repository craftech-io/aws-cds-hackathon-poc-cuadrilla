# FL-044 · Validación manual en la consola

| Campo | Valor |
|---|---|
| Área | E · Evidencia fotográfica |
| Actores · canal | Supervisor (consola) · consola, WhatsApp |
| Disparador | "Validar manualmente" sobre un ítem `REJECTED` o `IN_REVIEW`, con motivo |
| Reglas | Validación manual humana (ADR-0011) |
| Pruebas | U `routers/evidence.test.ts`, `services/evidence-override/override.test.ts` · UI `evidence.spec.ts`, `order-detail.spec.ts` · SR `SC-13/1..2` |

## Entrada

- `SC-13`: clon de `wo-24820` con preset `checklist {ONU_LABEL_PHOTO: REJECTED}`.
- `console.evidence.override({item: ONU_LABEL_PHOTO, reason})` con principal `SUPERVISOR` y `authTime` reciente; después, con `OPS` y con `SUPERVISOR` de `authTime` hace 20 minutos.

## Pasos

**SR · `SC-13`**

1. `SC-13/1` [det] `evidence.override` como `SUPERVISOR` con login reciente → `OVERRIDDEN` y turno `EVIDENCE_OVERRIDDEN` encolado.
2. `SC-13/2` [det] `OPS` → 403; `SUPERVISOR` con `authTime` de hace 20 minutos → 403.

**Local**

- U `routers/evidence.test.ts`: `evidence.override` con `supervisorProcedure` y `recentLoginProcedure` (login ≤ 15 min); motivo obligatorio.
- U `override.test.ts`: `override_evidence` escribe `OVERRIDDEN` con `overriddenBy`, motivo y hora, y encola `AGENT_TURN(EVIDENCE_OVERRIDDEN)`.
- UI `evidence.spec.ts`: "Validar manualmente" pide motivo y confirma.
- UI `order-detail.spec.ts`: con el login de más de 15 minutos, aparece el modal de contraseña antes de la acción.

## Resultado esperado

- `CHECK#ONU_LABEL_PHOTO` `OVERRIDDEN` con `overriddenBy` (usuario de consola), motivo y hora simulada.
- `AuditLog ACTION EVIDENCE_OVERRIDDEN` con el `userId`.
- Un `AGENT_TURN(EVIDENCE_OVERRIDDEN)` encolado para el instalador (el contenido del aviso no se asierta).
- `OPS` y `SUPERVISOR` sin login reciente: 403, el ítem no cambia y la denegación queda en la bitácora.
- Si la orden se cierra después, el acta muestra el ítem "validado manualmente por <nombre>" (`docs/architecture.md` §11).

## Oráculo

No aplica: todos los pasos son `det`.

## Evidencia

- `snapshot` del ítem antes y después; filas de `AuditLog` con `userId` y regla.
- Código de respuesta de cada principal (200/403).
