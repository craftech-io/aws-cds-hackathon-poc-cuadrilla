# FL-095 · Eventos de otro número de WhatsApp

| Campo | Valor |
|---|---|
| Área | K · Canal vivo y robustez |
| Actores · canal | Otra POC (simulada por el `QaDriver`) · SNS |
| Disparador | Evento con la forma real y otro `phone_number_id` publicado en el topic propio |
| Reglas | ADR-0002, `docs/architecture-integrations.md` §4.4 |
| Pruebas | U `channels/whatsapp/phone-filter.test.ts` · SR `SC-12/2`, `SC-17/7` (pendiente P-01) |

## Entrada

- `SC-12`: `wa.publishForeign` publica en `aws-cds-hackathon-poc-cuadrilla-wa-inbound` un evento con la forma real y un número ajeno (por código se niega a usar nuestro `WhatsAppMetaPhoneNumberId`) con el atributo `qa-foreign=1`.
- `SC-17/7`: prueba viva con la WABA propia (P-01, opción A).

## Pasos

**SR**

1. `SC-12/2` [det] `wa.publishForeign` → `probe.foreign`, sin efectos (`world.settle`); `ForeignPhoneNumberEvents` +1 como chequeo secundario.
2. `SC-17/7` [det] (pendiente P-01) durante la prueba viva, `ForeignPhoneNumberEvents` no suma nada fuera de los eventos `qa-foreign` del ejecutor.

**Local**

- U `phone-filter.test.ts`: con ids de forma real, el evento propio pasa; un filtro que comparara contra el id de AWS falla el caso; `MetaPhoneNumberIds` con otro ARN o cuenta → ajeno; un cambio con otro `metadata.phone_number_id` → ajeno; un cambio sin `metadata` → descartado; `qa-foreign=1` → descartado; `SigningCertURL` de otro host → rechazado; sobre simulado de un mundo vivo → rechazado; ningún log con contenido; nunca lanza.

## Resultado esperado

- `Runtime/PROBE#foreign#<messageId>` escrito (solo id y hora) y encontrado por `probe.foreign`.
- Ningún `Message`, turno, media ni log con contenido del evento.
- `InboundWhatsApp` devolvió éxito (sin reintentos de SNS).

## Oráculo

No aplica: todos los pasos son `det`.

## Evidencia

- Resultado de `probe.foreign` y su latencia; métrica `ForeignPhoneNumberEvents` como chequeo secundario (con la demora de CloudWatch).
- Conteos del mundo (`Message`, `TURN#`, objetos de media) antes y después (sin cambio).
